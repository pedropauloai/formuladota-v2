# Phase 1.5 — Doutrina: PLAN.md (retrospectivo)

> Plano reconstituído após implementação direta. Mostra a estrutura que GSD-planner teria gerado se a phase tivesse passado pelo workflow formal.

## Goal

Toda jornada de cliente novo passa por aceite obrigatório dos 14 princípios + 10 anti-padrões da Fórmula do Dota de Corrida ANTES de poder comprar pacote, agendar partida ou interagir com o sistema. Violações da cultura aceita geram advertência → suspensão → banimento progressivo, com auditoria completa.

## Success criteria

1. ✅ User logado SEM aceite que tente acessar `/perfil` ou qualquer rota privada → redirect pra `/onboarding/doutrina`
2. ✅ Aceite gravado no DB com versão (`doctrine_accepted_at` + `doctrine_version`)
3. ✅ Texto canônico do Pedro citado literal — sem paráfrase Cowork/Claude
4. ✅ User com `behavior_status = 'suspended'` e `suspended_until > now()` → redirect pra `/suspended` com motivo registrado visível
5. ✅ User com `behavior_status = 'banned'` → redirect pra `/banned` com motivo + link Discord pra contestar
6. ✅ Trigger `apply_warning_progression()` aplica regra 3-strikes automaticamente quando warning é registrado com `status='aplicada'`
7. ✅ RLS em `purchases` bloqueia INSERT se user não aceitou doutrina ou status não está ativo
8. ✅ Build/typecheck/lint todos passando

## Decisões de design (registradas)

- **5 slides** (não 12 como originalmente sugerido) — densidade alta sem ficar enciclopédia.
- **Sticky progress bar no topo** + **navegação fixa no rodapé** com "anterior/continuar".
- **Aceite explícito via checkbox + botão** — duplo gate evita aceite acidental.
- **Versionamento server-side** — Server Action confere `acceptedVersion` recebido vs `DOCTRINE_VERSION` atual.
- **Cards com border accent** — primeira regra (princípio #1) destacada com border cyan + glow.
- **Anti-padrões com `✕`** + cor danger — diferencia visualmente de princípios positivos.
