### Confirmação de disponibilidade (HIGH confidence — verificado via `font-data.json` do Next 16.2.4)

| Font | Pesos disponíveis | Status |
|------|-------------------|--------|
| Cinzel | 400, 500, 600, 700, 800, 900, variable | DISPONÍVEL |
| Marcellus | 400 | DISPONÍVEL |
| Inter | 100-900, variable | DISPONÍVEL |
| Space Grotesk | 300-700, variable | DISPONÍVEL (remover) |
| JetBrains Mono | 100-800, variable | DISPONÍVEL (remover) |

### Padrão correto para `src/app/layout.tsx`

```typescript
import { Cinzel, Marcellus, Inter } from "next/font/google";

// Heading de impacto: H1, H2 hero, CAPS
const cinzel = Cinzel({
  subsets: ["latin"],
  weight: ["600", "700", "900"],
  variable: "--font-cinzel",   // CSS var que next/font injeta
  display: "swap",
});

// Subheadings, quotes, taglines
const marcellus = Marcellus({
  subsets: ["latin"],
  weight: ["400"],
  variable: "--font-marcellus",
  display: "swap",
});

// Body, nav, buttons, forms
const inter = Inter({
  subsets: ["latin"],
  weight: ["400", "500", "600", "700"],
  variable: "--font-inter",
  display: "swap",
});

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html
      lang="pt-BR"
      className={`${cinzel.variable} ${marcellus.variable} ${inter.variable}`}
    >
      <body className="min-h-screen flex flex-col">
        ...
      </body>
    </html>
  );
}
```

### Por que usar `variable` (não `className`)

O padrão `variable` injeta a font como CSS custom property (`--font-cinzel: 'Cinzel', ...`) na tag `<html>`. O `globals.css` então referencia essa var no `@theme`:

```css
@theme {
  --font-display: var(--font-cinzel, 'Cinzel', Georgia, serif);
  --font-serif: var(--font-marcellus, 'Marcellus', Georgia, serif);
  --font-sans: var(--font-inter, 'Inter', system-ui, sans-serif);
}
```

Isso permite usar `className="font-display"` (Tailwind) em qualquer componente para aplicar Cinzel — exatamente o padrão já estabelecido no codebase com Space Grotesk.

**Pitfall crítico:** A variável CSS do `next/font` usa o nome que você definir em `variable`. No código atual é `--font-display` (Space Grotesk aponta direto pra `--font-display`). Para a nova estrutura, use nomes intermediários (`--font-cinzel`, `--font-marcellus`, `--font-inter`) e faça o alias no `@theme`. Isso evita conflito de nomes.

### Acessibilidade (prefers-reduced-motion)

Decisão de design: V1 respeita `prefers-reduced-motion` via `media` attribute na tag `<source>` ou via CSS. A abordagem mais simples em React:

```tsx
// Ler preferência via CSS (sem JS extra)
// O video continua presente mas com autoplay desabilitado via atributo condicional
// Implementação via hook useReducedMotion ou media query em CSS:
// @media (prefers-reduced-motion: reduce) { video { display: none; } }
// E mostrar o poster como <img> estático nesse caso
```

Para V1: usar `poster` como fallback visual + CSS `@media (prefers-reduced-motion: reduce) { video { display: none; } }` com `<img>` estático escondido por padrão. Isso cobre WCAG 2.1 SC 2.2.2 (Pause, Stop, Hide).

### Performance: LCP e hero video

O video de homepage tem 24MB — pode derrubar LCP se não for tratado. Estratégia:

1. `preload="none"` — não faz download até usuário chegar na viewport
2. IntersectionObserver para começar carregamento só ao entrar na tela (ou próximo)
3. `poster` com imagem estática como placeholder visual durante carregamento
4. O video fica com `position: absolute; inset: 0; z-index: -1` — não bloqueia LCP do texto H1

**Impacto real em LCP:** o H1 text é o LCP element, não o video. Se o video ficar `z-index: -1` e o texto for renderizado imediatamente (Server Component), LCP não é afetado.

## 9. Padrões Anti-Pattern a Evitar

### Anti-pattern 1: Tailwind classes hardcoded após rebrand

**Errado:** `className="text-[#00F0FF]"` (hardcoded)
**Correto:** `className="text-brand-red"` ou `style={{ color: 'var(--color-brand-red)' }}`
Usar tokens semânticos pra facilitar futuros rebrand (V3, V4).

### Anti-pattern 2: `font-serif` colidindo com utility padrão Tailwind

Tailwind v4 pode ter conflito entre `--font-serif` do `@theme` e a utility `font-serif` padrão do framework. **Usar nome distinto**: `--font-marcellus` no CSS variable, `font-serif` como alias no `@theme`. Testar com `pnpm build` para confirmar sem conflito.

### Anti-pattern 3: `next/font/google` com `weight` incorreto para Marcellus

Marcellus APENAS suporta weight `400`. Tentar `weight: ["700"]` vai quebrar o build com erro do next/font. Usar somente `["400"]`.

### Anti-pattern 4: Video Steam CDN em `<Image>` do Next.js

O `<HeroVideo>` usa `<video>` nativo — NÃO `next/image`. O `next.config.ts` atual não tem `remotePatterns` para `cdn.steamstatic.com` ou `cdn.akamai.steamstatic.com`. Adicionar patterns para imagens de poster, se usar `<Image>` para o poster:

```typescript
// next.config.ts — adicionar
{ protocol: "https", hostname: "cdn.steamstatic.com" },
{ protocol: "https", hostname: "cdn.akamai.steamstatic.com" },
{ protocol: "https", hostname: "cdn.cloudflare.steamstatic.com" },
```

### Anti-pattern 5: Usar `className="font-display"` esperando que seja Inter

Após o rebrand, `font-display` mapeia para **Cinzel** (não Inter). `font-sans` mapeia para **Inter**. Verificar que body text e nav usam `font-sans`, e apenas headings usam `font-display`.

### Anti-pattern 6: Deletar `--color-danger` junto com cyberpunk

`--color-danger: #ef4444` é uma cor sistêmica (erros, banimento) — MANTER. Só deletar `--color-cyan` e `--color-purple`. `/banned/page.tsx` usa `var(--color-danger)` — correto e deve ser mantido.
